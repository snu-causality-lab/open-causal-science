| Location in revision | Scope of change and current evidence |
| --- | --- |
| Section 2, Proposition 2 and Appendix B | `marginal_recorded` proves that the initial marginal history contains every unordered pair. `required_history_at_query` proves that each lower-order query specified in Proposition 2 was executed and returned dependence for an edge surviving to the current query. The executable scan stops after the first independence. The theorem assumes nested skeletons and candidate coverage from the tested side for subsets whose edges survive the earlier level. `required_history_of_frozen_neighbors` also handles frozen neighborhoods at the start of the current level. These are the schedule conditions for the proof. Relating a particular PC-stable scheduler to these conditions remains open. [Lean module](../../OpenCausalScience/Papers/KimLee2026DFPC/QueryHistory.lean) |
| Section 3.1, query history | The explanation distinguishes queries actually executed from lower-order queries that could have been posed. The history theorem recognizes swapped endpoints and permutations of the conditioning set. The cache proof uses the supplied query order as the lookup key. A history entry can therefore require canonicalization before exact-key reuse. |
| Section 3.2, early stopping | The revision states that lower-order histories in finite samples can change with traversal order. The public implementation retains early stopping by default and offers `early_stopping=False` as an option for `PCStable`. This observation concerns finite-sample histories and emitted skeletons. [Pinned code and option](https://github.com/snu-causality-lab/DF-PC/commit/b1c320027b7a8be8b31a2b751f51135fcb3e8c34) |
| Algorithms 3–4 and Appendix D | `deduceHelper_sound` proves the recursive helper returns only sound decisive answers and preserves cache soundness under the stated singleton conditional independence laws. `deduce_usesCIT_iff` characterizes exactly when it falls back to the oracle. `deduce_sound` proves the returned answer equals the exact oracle and recording it preserves cache soundness. `runDeduce_from_empty` preserves the primary query transcript and terminal result for any finite adaptive query plan. Cache keys retain the supplied endpoint and conditioning order. [Lean module](../../OpenCausalScience/Papers/KimLee2026DFPC/DeductiveCache.lean) |
| Sections 4–5 and robustness experiment | The released implementation reports skeleton discovery. Runtime comparisons are qualified by the tested conditions. The robustness setup's high-order oracle responses are exact, while deductions can still use erroneous lower-order inputs. These are implementation and experimental qualifications. |
| Experiments 8–9 | The revision identifies the preferential-attachment parameter as `D/2` in Experiment 8 and `D` in Experiment 9. Matching `D` across graph families is not an average-degree match. The revision keeps the reported experimental results. |
